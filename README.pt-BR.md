> Um Skill para Codex que transforma um projeto GitHub real e existente em um repositório mais claro, confiável e pronto para publicação, sem alterar o código do produto.

O GitHub High-Star Optimizer melhora somente a camada pública e de lançamento: posicionamento, estrutura do README, recursos visuais baseados em evidências, metadados, Release Notes, apresentações localizadas e materiais éticos de divulgação. Ele não promete Stars nem manipula engajamento.

> A fonte canônica é o [README em inglês](README.md). Esta tradução ainda não foi revisada por uma pessoa nativa; em caso de diferença, consulte a versão inglesa.

## O que ele otimiza

- **Clareza:** público, problema, resultado, diferencial e próxima ação.
- **Confiança:** afirmações ligadas a evidências do repositório, limites explícitos e resultados reais.
- **Apresentação:** README Hero, Social Preview, arte de Release, badges e hierarquia da informação.
- **Distribuição:** metadados, Release Notes, textos localizados e uma sequência mensurável de lançamento.
- **Limites:** não altera código-fonte, dependências, build, testes, CI, configuração de execução ou comportamento.

## Quatro modos

| Modo | O que acontece | Alterações |
|---|---|---|
| **Audit** | Avalia a superfície pública e prioriza lacunas. | Nenhuma |
| **Prepare** | Cria textos e recursos em um diretório separado. | Nenhuma |
| **Apply** | Aplica apenas arquivos não relacionados a código que tenham sido aprovados. | Lista aprovada |
| **Publish** | Atualiza metadados, Releases ou superfícies externas após autorização. | Somente ações autorizadas |

## Início rápido

1. Clone este repositório.
2. Copie o diretório interno [`github-high-star-optimizer`](github-high-star-optimizer) para o diretório de Skills configurado no Codex.
3. Invoque o Skill indicando um repositório ou workspace real.

```text
Use $github-high-star-optimizer to audit this existing repository.
Only optimize its public presentation and release package; do not change code.
```

## Regras de autenticidade

Toda afirmação importante deve vir de arquivos, Releases, demonstrações, Issues, fatos fornecidos pelo usuário ou inferências claramente identificadas. Imagens geradas não podem inventar interfaces, saídas de comandos, métricas, integrações, clientes, recursos ou Stars. Compra ou troca de Stars, interação automatizada e recompensas condicionadas são proibidas.

Veja o fluxo completo em [`github-high-star-optimizer/SKILL.md`](github-high-star-optimizer/SKILL.md) e as regras multilíngues em [`multilingual-publishing.md`](github-high-star-optimizer/references/multilingual-publishing.md).
